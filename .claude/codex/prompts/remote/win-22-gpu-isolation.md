WIN-22 — isolate who causes the GPU-process exit on the Vega 8: Chromium/Electron itself, or HimmelCAD's viewer. Host DESKTOP-BNB2PBA, clone C:\Users\flori\source\HimmelCAD (rules as WIN-20; logs under .build\win-22\; no commit/push; hard stop 45 minutes; one step at a time, each launch ≤ 2 min). Facts: WIN-20/WIN-21b — with AMD driver 31.0.12027 AND the new 31.0.21925.1001 every Builder launch logs `GPU process exited unexpectedly: exit_code=34`, then Chromium runs with software compositing/readback. Chromium's result code 34 is RESULT_CODE_GPU_EXIT_ON_CONTEXT_LOST: the GPU process exits deliberately after a context/device loss — so something loses the device. Hypothesis to test: our viewer's startup (WebGPU/wgpu adapter+device request, surface configuration, first pipeline/shader compile, or a large allocation) triggers a D3D device removal (TDR / DXGI_ERROR_DEVICE_REMOVED) on this iGPU.
Steps, five cold launches each, using the repo's Electron binary (`node_modules\.bin\electron` / scripts\run-electron.mjs pattern) with `--enable-logging --v=1` and a fresh `--user-data-dir` under .build\win-22\<case>\: (A) minimal main.js that opens `about:blank` — no HimmelCAD code; (B) same, loading `chrome://gpu` and dumping feature status via `app.getGPUFeatureStatus()` after 20 s; (C) a static HTML page with a plain WebGL2 canvas drawing a triangle for 20 s; (D) a static page doing WebGPU `requestAdapter()`/`requestDevice()`, configuring a canvas context and clearing it each frame for 20 s; (E) Builder (dev) with the DEV override `VITE_HIMMELCAD_VIEWER_BACKEND=webgl2` (landed in a902ac6: forces the viewer to WebGL2 before the first surface); (F) Builder default (WebGPU). For every case record: count of `exit_code=34` lines, time of the first exit relative to launch, the last 30 GPU-process log lines before it (look for `DXGI_ERROR_DEVICE_REMOVED`, `DEVICE_HUNG`, `Device lost`, Dawn/ANGLE messages), final `gpu_compositing`/`webgl2`/`webgpu` status, and the Windows event log entries of source `Display` (event 4101 "display driver stopped responding") in the launch window (`Get-WinEvent -FilterHashtable @{LogName='System';ProviderName='Display'}`).
