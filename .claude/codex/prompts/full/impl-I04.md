MASTER-PLAN row (verbatim): "Replay representative docs, TS, Rust, viewer, and release plans serially; capture ordered task set, result, wall time, peak CPU/RAM, and first-failure behavior. Execute independent tasks concurrently with a configurable cap; serialize tasks sharing output dirs, package staging, external targets, or mutable fixtures; cancel safely after failure. Gate `G-INFRA-RUNNER`: planned task set and pass/fail result are identical; conflicting tasks never overlap; 10 repeated runs have no flakes/orphans; report critical path, wall-time delta, peak resources, and first-failure latency."

Design constraints (architect):
- Each task declares resource keys (e.g. `cargo:target/builder`, `pnpm-store`, `wasm-staging`, `fixture:<path>`, `port:<n>`); tasks sharing any key never overlap. Cargo tasks share one key per CARGO_TARGET_DIR lane — two cargo invocations in the same target dir must never run concurrently (this caused index corruption before). Node typecheck/test tasks of different packages may run concurrently.
- Cap via `--jobs N` / `VERIFY_JOBS`, default = min(4, cores/2). Serial mode (`--jobs 1`) must produce byte-identical task ordering to today's runner.
- First failure: stop launching new tasks, let running tasks finish or send SIGTERM then SIGKILL after 10 s, exit nonzero with the first failing task's status. No orphan processes: verify with a process-group check in the test.
- Report (`.build/verify/timings.json`, extend the existing format, do not rename fields): per-task start/end/duration, resource keys, critical path, wall-time serial-vs-parallel delta, peak RSS (from /proc or `ps`, sampled), first-failure latency.
- Keep `verify:changed/commit/push/release` CLI unchanged; tests in `scripts/verification/*.test.mjs` run via `pnpm verify:matrix:check`.
- Evidence file `docs/builder-program/evidence/I-04-parallel-verifier-2026-09-02.md`: before/after measurements of a representative `verify:changed` plan (serial vs `--jobs 4`), 10 repeated runs of a small plan with no flakes (report exact counts), equivalence of planned task sets (diff of ordered task ids), and the conflict test proving two cargo tasks on one lane never overlap.
