# Shapr3D gap inventory — HimmelCAD Assembler

Owner intent U2 (`OWNER-INTENT.md`): get as close as possible to Shapr3D in
functionality, workflow, UI, mouse/touch operation and feature interactions,
and **maintain a feature/behaviour gap inventory**; milestone reductions do not
redefine the end goal. This is that inventory. First written 2026-09-30
(branch `asm/gaps-20260930`); keep it current whenever a row changes.

## Method

- **Shapr3D side** — only what the research archive
  `research/2026-09-28/` documents, with its evidence tags: **D** official
  documentation/transcript, **V** actually viewed image/video frame, **I**
  our implementation inference, **O** open. Sources: `notes/interaction.md`
  (`int §n`), `notes/modeling.md` (`mod §n`), `notes/scope-media.md`
  (`scope §n`), `notes/coverage-audit.md` (`audit`), `notes/tutorial-catalog.md`
  (134 official tutorial entries, `tut:<title>`), `Report.md`. No behaviour
  was added from memory; where the archive itself says **O**, the row says so.
- **Assembler side** — verified in the running app, not from the docs:
  `pnpm dev:web` + the DEV hook `window.__assembler` (new `commands` member:
  registry list, adaptive order, search results, `run`), probe script
  `D:\AgentWork\HimmelCAD-Assembler\shots\g-probe.mjs` → `g-probe.json`
  (134 commands; adaptive order for 10 selection shapes; search results for
  9 queries), plus code/test reading for details the probe cannot reach.
- **Status** — `done` (behaviour as documented), `partial` (exists but
  differs: other commit/cancel semantics, missing variants, missing adaptive
  suggestion, missing option …; strict), `missing`, `deferred-by-owner`
  (cloud, 2D drawings, XR — `OWNER-INTENT.md` "Cloud, drawings, XR"),
  `blocked-by-kernel` (needs geometry OCCT/our kernel adapter cannot do yet
  without a research spike).
- **Effort** S ≤ ½ day, M 1–3 days, L > 3 days or research. **Value** 3 =
  everyday modelling/printing workflow, 2 = regular, 1 = occasional.
- **Parity estimate** — per row score done = 1, partial = 0.5, missing /
  blocked = 0; weight = value (1–3); `deferred-by-owner` rows are excluded
  from the ratio and reported separately. Weighted parity = Σ(value × score)
  / Σ(value). This measures _documented behaviours covered_, not pixel
  similarity or kernel-identical results (Parasolid vs OCCT, `Report.md`
  "K"), and every row counts once regardless of its size — a big row such
  as Visualization weighs the same as a keyboard shortcut. Read it as a
  trend indicator between revisions, not as "percent done".
