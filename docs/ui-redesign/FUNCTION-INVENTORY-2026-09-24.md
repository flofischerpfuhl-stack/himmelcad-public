## 13. Conflicts and open points

1. Tabs: D2 (OD:57) says File, View, Pointcloud, Draw, Mesh, BIM, Raster, with Plan and Agent as windows. Today's tabs are File, Edit, View, Select, Pointcloud, Draw, Mesh, Inspect, Output. The owner needs to pick the final set.
2. REG disagrees with itself on group placement. Measure is under "Inspect · Measure" (REG:232) but also "View · Measure" (REG:235). Box and Lasso are "View · Selection" (REG:246), yet the ribbon has a separate Select tab.
3. Owner rule (3) says roles are set only in the surface tool. But `draw.boundary` sets the boundary role while drawing (REG:145; `packages/@himmelcad/app/src/drawing.ts`:138).
4. Owner rules (1) and (4) conflict with the DGM window. It still has "Thin cloud" and "Boundary role is 2D crop" (`apps/builder/renderer/src/DgmCreationWindow.tsx`:188,191).
5. Owner rule (5) conflicts with MTS:250, which still lists "Breakline vertex off the point set" as an error. Check whether the code still reports it.
6. Owner rule (1) says every vertex with a finite Z is an elevation point. `draw.assign-heights` and DRS:793 still speak of "plan-only entities" that are hidden in 3D. The owner should confirm whether that 2D/3D admission survives.
7. ADR 0032 makes the CRS a declaration at scale 1, yet MTS:952 calls volume "CRS-explicit". Confirm that no CRS affects the volume computation. A project-CRS entry also has no UI home yet.
8. Save: D1 wants a Save dropdown with "Save snapshot…" and "Save As…". Today Save As appears twice, and creating a snapshot is automation-only (RIB:126-169).
9. Specifications: the shipped window keeps its library in browser storage (SpecsIsland.tsx). REG:201 says it is superseded, and D2 moves specs to a BIM tab.
10. Plan: the shipped plan is a floating island. PE-D1 (REG:274) wants a separate OS window, and PE-D3 says "finite-paper canvas" while D7 (OD:179) says "infinite canvas + floating islands".
11. Civil has no tab of its own; it sits in Draw/Mesh (REG:355), while ADR 0032 lists Registration as its own domain module. The owner should decide whether Civil and Registration get their own tabs.
12. The 1.0 goal (S16, MP:431-432) names "split" line editing, which has no registry row. It also names 2D and 3D distance, which may be one tool or two.
13. Five rows are "cataloged-deferred" in the specs only, not by the owner: pattern, fragment, selective undo, cloud→mesh, texture. The owner should say whether the redesign shows them.
14. Import rejects TZF/TDX, ZFS, RCP, JXL and RVT as a class (IFS:109). That is a spec decision the owner has never confirmed, and these are the Trimble/Autodesk formats pilot offices use.
15. D1–D5 still read "pending" in the status table (OD:344-348). D8 is also pending, yet the 1.0 definition rests on it. Treat them as accepted?
16. REG is out of date in both directions. It lists as missing things that exist (`file.new`, jobs island, toasts), and some of its "implemented" rows have partial UI (support overlay, labels). It needs a status refresh after the redesign.
17. Several shipped commands are console-only: section/clip, opacity, vertical exaggeration (APP:3914). The redesign needs visible entries or a decision to drop them.
18. The navigation-mode and viewing-box ribbon ids (`view.3d/2.5d/2d`, `view.viewing-box`, `view.point-size`, `output.*`, `automation.agent`) are hand-wired outside the generated command table. ADR 0032 wants a single table.
19. Owner boundary rule 2026-09-08 (`docs/history/photolab/PHOTOLAB-HANDOFF-2026-09-11.md`:121): editing published PhotoLab products belongs to Builder. That covers mesh repair/decimation, breaklines, seamlines and contours. Seamline editing has no Builder row.
20. There is no "DEFERRED from 1.0" owner decision. 1.0 = M-RW + splat display (MP:100). Civil, full BIM, Plan and Agent depth sit outside it but are not explicitly excluded. The owner should state the 1.0 cut for the redesign.
