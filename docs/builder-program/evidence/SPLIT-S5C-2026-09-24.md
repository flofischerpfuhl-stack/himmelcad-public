# Split step 5c evidence — photogrammetry domain

Date: 2026-09-24

## Result

Step 5c creates the `domain`-layer crate `himmelcad-domain-photogrammetry` and gives it the PhotoLab contracts, project storage, worker orchestration, and photogrammetry algorithms that were previously split between `himmelcad-core`, `himmelcad-command`, `himmelcad-io`, and `himmelcad-sidecar`. The new crate has no dependency on `himmelcad-command` or another domain crate.

The move preserves the existing Rust module paths for consumers through ordinary Cargo dependency renames and re-exports. There are no cross-crate `include!` directives, exported domain macros, generated cross-crate source, duplicate type definitions, or new/widened allowlist entries.

`photolab_capture` and `photolab_images` now share one owner for their common capture vocabulary: `capture_contract.rs`. `PhotoFormat` is defined there and re-exported from `photolab_images` for compatibility.

## 5c-fix

### Result

The crate-name compatibility aliases described above were removed. Every
workspace dependency now uses its package's real Cargo name. In particular,
`himmelcad-sidecar` has separate direct edges to `himmelcad-core`,
`himmelcad-domain-photogrammetry`, `himmelcad-document`, `himmelcad-model`,
`himmelcad-prepared`, `himmelcad-process`, and `himmelcad-transform`; Builder
foundation paths no longer resolve through the PhotoLab domain crate.

The photogrammetry crate no longer declares `extern crate self as ...`, exposes
blanket foundation modules, or supplies the `raster_runtime`,
`pointcloud_export`, and `dense_raster_prep` shim modules. Moved code uses
`crate::...` for PhotoLab-owned modules and imports model, document, prepared,
process, and transform contracts from their actual crates. The remaining root
re-exports come only from the photogrammetry crate's own import modules. There
is no `pub use` of a foundation crate anywhere in the photogrammetry crate.

The command compatibility facade and worker-toolchain consumer name
`himmelcad-domain-photogrammetry` explicitly. Sidecar PhotoLab paths name that
domain explicitly; generic cancellation, archive, canonical model, prepared
scene, and transformation types use their real foundation crates. No schema,
serde attribute, default, algorithm, file format, wire contract, or timing bound
was changed. The Rust test annotation count remains **1,237**.

## Architect review (2026-09-24)

The first 5c result moved the code for real but hid dependencies through
crate-name aliasing (a `package =` rename of the photogrammetry crate to
`himmelcad-core` in the sidecar, `extern crate self as himmelcad_core` /
`himmelcad_sidecar`, blanket foundation re-exports). 5c-fix removed them and the
checker now rejects both patterns. Architect re-run: workspace check green, fmt
clean, checker ok (8/8 fixtures), photogrammetry 377 passed, frozen routes 3/3,
sidecar bins 13 + 38 passed, sidecar lib 65 passed with the known group-commit
p95 timing gate failing only under load (passes alone), Rust test count 1,237,
`cargo tree -p himmelcad-sidecar --depth 1` shows the true edges.
