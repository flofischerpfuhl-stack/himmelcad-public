shared kernel React adapter. Builder and PhotoLab renderer code was not
changed. The viewer package exposes only `@himmelcad/viewer/kernel` and
`@himmelcad/viewer/kernel/react`.

capture at 08:38:20 CEST through the final evidence and diff audit at

## Kept because used

No kernel file imported any of the named legacy files or any file in the
legacy-only closure; therefore there is no legacy file to retain. The scan of
`src/kernel/**` found no parent-directory imports. In particular,
`src/kernel/KernelViewport.module.css` remains because it is imported by the
live kernel React adapter.

Kernel tests containing the word `legacy` remain where they test supported
legacy 3D Tiles/Potree metadata or project migration semantics; they do not
import or exercise the removed Three.js viewer.

## WeltView

`apps/weltview/src/App.tsx` now imports `KernelViewport` from
`@himmelcad/viewer/kernel/react` and its loader type from
`@himmelcad/viewer/kernel`. It uses the same `viewer-wasm/` and
`viewer-decode-wasm/` URL contract as Builder and PhotoLab. The existing ribbon,
entity panel, function panel, read-only bottom panel, and status bar remain.
The status bar maps the active kernel pick's `snapKind`; no entity, dataset, or
product loading was added.

  WeltView production build passed, but deployment of its external WASM files
  was not exercised in a browser.
- No real dataset or product-loading run was performed; WeltView intentionally
  remains an empty read-only shell.
