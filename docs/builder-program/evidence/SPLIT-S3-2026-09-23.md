# Split step 3 evidence — lower model and prepared contracts

Date: 2026-09-23 (Europe/Berlin)

## Result

Step 3 creates the foundation crates `himmelcad-model` and
`himmelcad-prepared`. `himmelcad-io` now depends on `himmelcad-prepared`, not
`himmelcad-render`; a source scan and `cargo tree -p himmelcad-io --edges
normal` find no `himmelcad-render` edge. `himmelcad-render` now depends directly
on both lower crates and no longer depends on `himmelcad-core`.

There is no schema, serde attribute, field-order, default, wire, or production
algorithm change. Old core and render paths remain compatibility re-exports.
The automation schema golden and frozen sidecar response corpus are unchanged.

The split leaves the stateful document implementation in core (1,338 lines),
the document-backed property query/edit implementation in core (508 lines),
and the public Release 0.5 admission algorithms and their tests in core (702
lines). The model has the identical private measurement invariant needed by
entity semantic validation; the public `validate_measurement` admission
algorithm remains in core at its old path.

Prepared owns `DatasetId`, `TileId`, world/bounds/transform contracts,
`ContentReference`, `HierarchySource`, `PreparedHierarchySource`, prepared
point metadata, `DecodedTriangleFeatureId`, and the Potree hierarchy/point
contracts needed by I/O. Renderer-specific decode, GPU, raster, mesh, and
sidecar preparation modules did not move.

## Cycle cuts

- Document/model/validation/admissions: `EntityVersionRef`, canonical object
  edit/mutation/journal DTOs, property-schema DTOs, and Release 0.5 DTOs now
  live in model. Core retains document state transitions, property compilation,
  and admission algorithms and depends downward on model.
- `typed_artifact`/registry: the reverse edge existed only in a unit test. That
  test is now the model integration test
  `tests/typed_artifact_registry.rs`; the production modules have one-way model
  ownership.
- I/O/render: hierarchy, tile, content, feature-ID, and Potree prepared
  contracts now live below both crates. I/O imports prepared directly. Render
  re-exports the types at the old crate-root and `providers` paths.
- Render/core: render imports model directly. This made its old core allowlist
  entry stale as part of the same lower-contract cut.
- The I/O-only renderer fixture helper and its calls were removed with the
  package edge. Provider packages remain covered by their I/O tests and render
  compilation/decoding remains covered by render tests, but the combined
  provider-to-render assertion is not re-homed in this step; a future neutral
  cross-crate integration harness should restore that combined coverage
  without introducing an architectural dependency.

## Compatibility and remaining consumers

`himmelcad-core` re-exports the moved whole modules under their old names.
`canonical_document`, `property_schema`, and `release_05_admissions` remain old
core modules and re-export their model-owned DTOs. `himmelcad-render` re-exports
all moved prepared contracts at the former public paths.

Consumers still using core compatibility paths:

- `himmelcad-io` (it also needs not-yet-moved core algorithms and PhotoLab
  contracts, so only its prepared imports changed in this step);
- `himmelcad-sidecar`;
- `himmelcad-wasm`.

Consumers still using render compatibility paths for moved prepared types:

- `himmelcad-decode-wasm`;
- `himmelcad-sidecar`;
- `himmelcad-wasm`.

Those migrations are intentionally deferred. Render itself was migrated to
model/prepared because that removes a complete stale edge. No sidecar module
was moved.

## Binding and wire identity

`@himmelcad/data` invokes the generator from `himmelcad-model`. The generated
barrel text was deliberately not renamed, so generated source bytes stay
identical. The checker reports `missing: []` and `changed: []`; its only failure
is the pre-existing treatment of all 588 tracked compiled `.js`, `.js.map`,
`.d.ts`, and `.d.ts.map` files as stale. The working generated tree has no diff
from `HEAD`.

This is demonstrably present on `HEAD`: the `HEAD` package script invokes the
old core generator, all 588 compiled artifacts are tracked on `HEAD`, and the
`HEAD` `check_equal` implementation compares every file returned by
`read_tree`, classifying every actual-only file as stale. The move did not
change that comparison.

- frozen sidecar route inventory and exact response corpus: 3/3;
- sidecar binary tests: 119/119 across the portable-MVS and main binaries;
