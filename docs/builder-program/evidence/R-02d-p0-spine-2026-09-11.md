## Finding → root cause → fix → test → screenshot

### P0-1 — New / project replacement isolation

- Finding: outgoing viewing-box, selection, residency, processing, and tool state could remain live while the replacement project was prepared.
- Root cause: replacement cleared only the canonical session and a subset of React state; lifecycle-sensitive refs, all `builder.*` jobs, cached viewing-box revisions, draw/fence state, and viewer residency did not share one reset boundary.
- Fix: `resetProjectRendererState` synchronously retires the old refs and then clears every project-owned React surface before `resetProjectScene`; replacement calls it before assigning the next path. Close cancels every active `builder.*` job. Residency refresh now publishes the new document revision only after its protocol URLs are resident, preventing the locked-box rebuild/404 race. See `apps/builder/renderer/src/App.tsx` around lines 1119, 1191, 1261, and 1447.
- Automated evidence: Builder project-replacement tests pass; Builder test suite 46/46 and typecheck pass.

### P0-3 — Draw publication all-or-none

- Finding: each accepted vertex was previously journaled, so Boundary Close and Finish could leave partially canonical geometry and then compensate it with undo.
- Root cause: the draw controller used the canonical entity itself as the in-progress draft.
- Fix: accepted vertices remain view-local. A line publishes once on its second vertex; Boundary Close and explicit Finish validate minimum cardinality and publish exactly once. A failed publish keeps the armed non-canonical draft and typed error for retry. Cancel and vertex undo have no canonical compensation. Exact first-point closure routes through the same finish transaction. See `packages/@himmelcad/app/src/drawing.ts` around line 191.
- Automated evidence: `DR-D5 Boundary Close publishes once and a failed close preserves a retryable draft` plus updated local-undo tests; app suite passes 80/80.

### P0-4 — DGM staged-provider publication

- Finding: Create failed with `canonical representation contract is invalid`; height grids were not resident and could not feed meshing.
- Root causes:
  1. authoritative canonical TIN representations incorrectly carried `dependency_hash`; dependency provenance belongs in the recipe/relations, while the baked canonical slot requires `None`;
  2. the old height-grid publication bound geometry directly to analytical HGRID bytes, not a viewer prepared hierarchy;
  3. the mesh reader initially opened the new viewer manifest as if it were HGRID bytes;
  4. Builder bounds extraction accepted only axis-aligned boxes, while the prepared TIN root uses a sphere;
  5. the export-side topology index reader rejected the additional canonical part fields (`bounds`, position/index/material URLs).
- Fix:
  - one `authoritative_baked_surface_representation` helper emits canonical/authoritative/`dependency_hash: None` for create and edit (`mesh_surface_runtime.rs`, around lines 861, 1285, 1468);
  - rasterization streams `height-grid.hgrid`, RGBA, and f64 elevation artifacts and publishes a validated `hcad.pointcloud.height-grid@1` prepared hierarchy without buffering a second full grid (`pointcloud_sampling.rs`, around lines 832–1011);
  - canonical inventory retains both viewer and analytical artifacts, and meshing resolves the exact `height-grid.hgrid` artifact with a legacy direct-object fallback (`canonical_app_runtime.rs`, around lines 1430 and 2438; `mesh_surface_runtime.rs`, around line 348);
  - Builder restores height grids as prepared hierarchy residents and derives finite AABBs from axis-aligned, spherical, or oriented-box volumes (`App.tsx`, around line 6821; `BuilderKernelViewport.tsx`, around line 3505);
  - export topology consumes its required fields while tolerating the other schema-defined part fields (`canonical_app_runtime.rs`, around line 4903).
- Automated evidence: canonical representation unit assertion and height-grid inventory/addressability assertions compile under the sidecar tests; final sidecar tests/bins check passes.
- Literal UI evidence:
  - height grid created and later reopened as `1 inline mesh`: `.build/r02d/74-height-grid-created-resident.png`, `.build/r02d/75-height-grid-reopened-resident.png`

### P0-5 — Fence picks

- Finding: an armed fence owned LMB click gestures but stale/failed GPU picks returned before the gesture arbiter could dispatch them, producing zero vertices.
- Root cause: click dispatch assumed every tool required a current scene hit. A screen-plane fence does not.
- Fix: `PlatformGestureArbiter.hasActiveClaim` exposes armed row ownership; the navigation controller dispatches a null candidate to an armed LMB claim after stale/failed GPU picking while retaining generation/navigation guards. Plane projection then either accepts the vertex or emits a visible rejected-pick warning. See `PlatformGestureArbiter.ts` around line 223, `KernelNavigationController.ts` around lines 889–901, and Builder callbacks around `App.tsx` line 5088.
- Automated evidence: viewer regression `an armed LMB geometry claim survives stale or failed GPU picking`; viewer suite passes 165/165.

### Interaction progress correction discovered during replay

The first segmentation emitted progress for essentially every visited point. The sidecar finished, but hundreds of thousands of renderer events left the visible UI stuck near 4% for minutes. Segment progress is now bucketed by phase and integer percentage (at most about 202 updates per source), with a unit assertion in `main.rs` around lines 1894, 1965, and 12173. This forced the renderer restart that prevents claiming the strict uninterrupted first chain.
