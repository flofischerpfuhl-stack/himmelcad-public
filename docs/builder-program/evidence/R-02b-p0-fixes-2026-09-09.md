## Finding-to-fix evidence

### P0-1 — New/project replacement

**Root cause.** Canonical artifact protocol reads were resolved against the
default project store even after another project became active. Once the
viewer was retained across replacement, two additional real-flow races became
visible: project display/selection effects could address entities after scene
retirement, and reopening an entity reused a first-publication generation
after the viewer had returned a tombstone generation.

**Why R-02 missed it.** The replacement unit covered a mocked open/close
coordinator. It did not perform an Electron protocol range read from the
auto-opened legacy project, nor exercise React effects and viewer slot
generations across a second live replacement.

**Fix.** Electron now binds protocol reads to `activeCanonicalProjectRoot` and
updates it on sidecar/lifecycle open and close. Builder retains the viewer but
retires project residency explicitly; unloaded selection/visibility effects
record desired state without crossing the kernel boundary. Returned canonical
tombstone bindings are retained and supplied as the expected generation on a
later load.

**Visible acceptance.** Auto-opened `r01-review-pass1`, invoked File → New,
used the native dialog with the spaced name `r02b new verified 2`, and obtained
a live fresh shell with one Default layer. The target contains manifest,
objects and journal entries 1–2. A subsequent fresh → legacy → fresh → legacy
replay completed without a page error or generation conflict.

### P0-2 — road cloud visibility and selection

**Root cause.** The wrong project-root binding made prepared hierarchy/range
reads inconsistent with the active canonical entity. Separately, the
selection store's entity catalogue was only populated at project open, so an
entity published later could appear in the tree without becoming an
admissible canonical selection.

**Why R-02 missed it.** Tests used a single default project and predeclared
catalogue entries. They did not reuse the reviewer's auto-opened project,
remove its old clip, and render/select the newly published 103.7 M entity.

**Fix.** Active-project artifact routing is canonical, project scene reset no
longer remounts the renderer, residency loads update the selection catalogue,
and newly loaded selected entities receive their interaction state only after
their canonical binding exists.

**Visible acceptance.** With the old box removed, View → Frame All rendered the
road and the tree/context Zoom to path retained selection. The physical window
shows the road, `aria-selected=true`, `Selected: 1`, and populated Properties.
The direct kernel capture contained 9,823 non-background pixels versus 252,321
background pixels (90,544 resident points, 9 draw calls) at the proof frame.

### P0-3 — legacy `default-layer` and atomic exact entry

**Root cause.** Opening a pre-R-02 document could find `default-layer` only as
a tombstone; the bootstrap attempted a second create rather than restoring the
system entity at its current revision. In the construction bar, controlled
NumberInput drafts committed on blur, and focus traversal could also make a
later Enter look unchanged and suppress its commit callback.

**Why R-02 missed it.** Fresh-project tests did not open an explicit legacy
tombstone state. Construction tests asserted markup, not X → Tab → Y → Tab → Z
→ Tab → return-to-Z → Enter behavior.

**Fix.** Canonical open now idempotently accepts a live default layer, restores
the tombstoned system layer, or creates it only when truly absent. Fresh
bootstrap contains one root and one default layer. Construction NumberInputs
retain drafts across Tab, never commit on blur, and always emit the explicit
Enter action even when a controlled preview already echoed the value.

**Visible acceptance.** In the spaced fresh project, exact X/Y/Z values plus
Tab left `Vertices 0`; returning to Z and pressing Enter changed it to
`Vertices 1`. Three exact vertices closed and stored `Boundary polygon 1`.
After reopening the legacy project, Inspect → Point stored `Point 1` on
`default-layer`; selecting it populated fixed XYZ Properties and no collision
message appeared.

### P0-4 — Viewing Box Lock progress, completion and cancellation

**Root cause.** Hierarchy proxy pages were fetched through one Electron range
request each, and every cached page/node awaited a cross-process progress
update. A large point node was filtered synchronously without yielding, so
input and abort could be delayed. Re-bakes also reused one proxy entity ID for
different published datasets, causing representation-generation conflicts.

**Why R-02 missed it.** Its fixture had one tiny hierarchy page and a tiny
point node. It did not include protocol round-trip cost, a multi-page prepared
hierarchy, a large filtering loop, or two bakes of one box entity.

**Fix.** The bake uses a bounded four-entry, 1 MiB hierarchy range-window cache,
prunes non-intersecting pages, throttles phase publication to meaningful
increments, and yields/checks abort every 65,536 point records. Published
proxy IDs include their dataset ID. Progress now names metadata, hierarchy,
filtering, publication and locked phases. UI cancellation flushes its state
before signalling the abort.

**Visible acceptance.** A sampled real LAS cell supplied a 10 m cube at X
2538170–2538180, Y 5486660–5486670, Z 380–390. The cache-miss lock progressed
1% → 3–9% → 10–90% → 98% → 100%, completed in 20.021 s under load, and
persisted 419,609 prepared points. A later cache-miss cancellation during
filtering returned from the click in 269 ms and exposed Lock again in 1.512 s;
the job reached cancelled state. The large-node unit cancellation completed in
56–84 ms in repeated Builder test runs.
