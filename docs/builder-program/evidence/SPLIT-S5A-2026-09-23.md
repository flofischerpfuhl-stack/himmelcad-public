# Split step 5a evidence — prepared-artifact producers and raster domain

Date: 2026-09-23
Repository revision at start: `36532ea2` (`main`)
Result: the eight-module sidecar SCC is cut without moving route dispatch or changing the frozen protocol.

## Resulting placement

The production dependency direction for this cut is now:

```text
sidecar COLMAP/integration code
  -> himmelcad-command
  -> himmelcad-domain-raster
  -> himmelcad-prepared
  -> himmelcad-process / document / model
```

`himmelcad-prepared` has no normal, build, or dev dependency on a domain crate, the
sidecar, COLMAP, or `himmelcad-render`. The four tests that exercise produced bytes
through upper renderer readers moved intact to the legacy sidecar compatibility
modules; all other producer tests live with the prepared producers.

`himmelcad-domain-raster` has production dependencies only on `document`, `model`,
`prepared`, `process`, and third-party libraries. It does not depend on the sidecar,
`himmelcad-command`, `himmelcad-render`, or another domain crate.

## How each cycle edge was cut

| Previous edge                                                                   | Replacement                                                                                                                                              |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `colmap_runtime -> mesh_tiler`                                                  | COLMAP imports `himmelcad_prepared::mesh_tiler::PreparedMeshProduct`.                                                                                    |
| `colmap_runtime -> prepared_triangle_mesh(_ply)`                                | Producers live in prepared; COLMAP and sidecar callers consume the lower crate or compatibility path.                                                    |
| `raster_runtime -> colmap_runtime`                                              | Shared worker launching and limit-mode selection moved to `himmelcad-process::worker`.                                                                   |
| `dense_raster_prep -> colmap_runtime`                                           | Dense preparation now imports the same lower worker contract directly.                                                                                   |
| `raster_runtime -> dense_raster_prep`                                           | Prepared dense result DTOs moved to `himmelcad-prepared::dense`; raster no longer imports dense sidecar code.                                            |
| `raster_runtime -> viewer_raster_manifest` and `viewer_raster_surface_manifest` | Runtime is in the raster domain and imports both publishers downward from prepared.                                                                      |
| `mesh_tiler` / viewer manifests `-> raster_runtime` DTOs                        | Shared raster summaries, grid/source/validity DTOs moved to `himmelcad-prepared::raster`.                                                                |
| `prepared_triangle_mesh -> mesh_tiler`                                          | Both producers are siblings in `himmelcad-prepared`; no sidecar/raster back-edge remains.                                                                |
| raster runtime `-> job_runtime` concrete sinks                                  | The raster domain owns narrow memory/checkpoint sink traits; `himmelcad-command::job_runtime` implements them and retains PhotoLab progress translation. |
| orthophoto preparation `-> sidecar mvs_runtime` DTOs                            | Neutral MVS scene DTOs moved to `himmelcad-prepared::mvs_scene`; the old MVS module re-exports them.                                                     |

Within the affected SCC, `colmap_runtime` now reaches worker/process and prepared
contracts only downward. Its unrelated same-sidecar orchestration collaborators
(`image_commit`, job scheduling, masks, feature databases, and DeDoDe) were not part
of this cut and remain for later sidecar splits. No prepared or raster-domain module
imports COLMAP.

## What stayed and why

- `dense_raster_prep` stays in the sidecar for step 5b. Its public processing API
  embeds `ground_classification::{Point3, PointClass}` and its bounded GDAL stages
  use the PhotoLab-specific `JobMemorySink`. Moving it now would require either a
  forbidden `prepared -> domain/command` edge or a wider classifier/memory contract
  extraction than step 5a. Its worker-launch dependency on COLMAP was still removed.
- `colmap_runtime` stays in the sidecar for photogrammetry step 5c.
- Route registration and dispatch stay in the legacy sidecar. The frozen route
  inventory and response corpus are unchanged.
- `package_prepared_triangle_mesh` is in `himmelcad-io`, not prepared, because it
  writes an IO-owned package and putting it in prepared would form an
  `io <-> prepared` cycle.
- The PhotoLab `GcpSimilarityTransform` adapter stays at
  `sidecar::splat_tiler`; the producer accepts a neutral, field-identical prepared
  transform.
