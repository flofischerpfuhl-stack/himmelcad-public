# Documentation audit — contradictions and compression plan (2026-09-23)

## Summary

- Scope read: 96 existing Part A files, 190,474 words, plus one requested missing path; targeted scan: 39 Part B specification files, 289,826 words.
- Findings: 8 authority/process contradictions, 6 owner-rule contradictions, 8 stale-status claims, and 4 missing/stale references (26 total).
- The highest-risk cluster is the old Builder program: it still presents autonomous Branch-A execution as active although the 2026-09-23 direction requires architecture first and then owner-agent UI co-design.
- The DGM specification still assigns a role at draw time, guesses roles, embeds cloud sampling, treats an off-point-set vertex as an error, and does not make finite-Z boundary vertices elevation inputs.
- ADR 0030 and ADR 0031 remain Proposed but are cited as if they authorize implemented normative contracts; owner disposition is required.
- Top fixes 1–5: correct the Master Plan authority order; mark the old Builder sequence superseded; add the Builder co-design exception; apply all five DGM corrections; remove implicit Z=0.
- Top fixes 6–10: resolve ADR 0030/0031 status; remove internal-project CRS transforms; correct the Windows host facts; close stale owner questions; fix three missing paths.
- Compression target: reduce Part A from about 190k to 55–70k words; replace about 290k words of Builder specs with 20–35k words of jointly designed UI/domain rules plus archived history.
- No source, documentation, code, or repository state was changed other than this report.

- **P3 — accepted architectural history:** ADRs 0001–0029, including reasons and rejected alternatives, remain in place; add superseding references instead of rewriting or deleting them.
- **P4 — unresolved admissions:** ADR 0030 and ADR 0031, both Proposed 2026-09-02, require an explicit owner accept/reject/supersede record. Their implemented schema facts stay in `DATA-MODEL.md`/`PROJECT-FORMAT.md`, clearly marked provisional until disposition.
- **P5 — PhotoLab product/release truth:** accepted ADRs 0005–0015, 0020–0024, 0028; 2026-09-05 triage; 2026-09-19 Windows/support decisions; remaining R1 gates. Keep decisions in ADRs/`OWNER-DECISIONS.md`, current gates in one short release-status file, and run evidence in history/evidence.
- **P6 — Cap truth:** ADR 0027 (2026-07-21), `.hcap` format/import boundary, privacy/accuracy posture, and field-validation gates. Keep in ADR 0027 plus short Cap product/format/roadmap specs.
- **P7 — research provenance:** source URLs/titles, access dates, license/provenance, and the exact conclusion each source supports. Keep in an owning spec’s References appendix or a dated `docs/history/research/` dossier.
- **P8 — verification history:** candidate hash, date, machine, exact command, result, and limitation. Move to `docs/history/` or the excluded evidence tree; only unresolved gates remain in live status.
- **P9 — shared UX/contract rules:** accepted owner corrections, accessibility, lifecycle, cancellation, command parity, and complete-flow requirements. Keep concise current rules in normative documents; unaccepted derivations remain labelled draft.
