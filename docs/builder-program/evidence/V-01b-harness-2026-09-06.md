# V-01b — Builder startup and viewer-baseline harness — 2026-09-06

> **Builder root-cause fix:** Builder was broken in two independent places. The
> Electron main bundle retained a runtime `require("@himmelcad/app")`, whose
> source-only entry then tried to import nonexistent `src/*.js` files, so
> Electron exposed CDP but never created a window. After fixing that, React
> repeatedly re-rendered the shell because `ViewDisplayStore.getSnapshot()`
> returned a new object on every read, ending in `Maximum update depth
> exceeded`. The Electron main is now bundled with its source-only app
> dependency, and the display store now publishes an identity-stable cached
> snapshot. Both failures have regression tests.

Status: **COMPLETE. Builder starts and renders its shell; the harness attaches,
records a non-blocked five-scenario report, rejects software adapters, and
cleans up its owned process tree and profile. The numbers are a contended
diagnostic capture, not a quiet-machine qualification.**

## Builder health and root causes

The initial normal launch was:

```sh
CARGO_TARGET_DIR=target/builder DISPLAY=:0 \
  pnpm --filter @himmelcad/builder dev
```

The first failure occurred before `createWindow()`. The emitted Electron main
loaded `@himmelcad/app` at runtime, while that package's runtime entry is
`src/index.ts`; Node then reported:

```text
Error [ERR_MODULE_NOT_FOUND]: Cannot find module
'.../packages/@himmelcad/app/src/clients.js' imported from
.../packages/@himmelcad/app/src/index.ts
```

That exactly explains the V-02/D-02 symptom: the browser process had already
opened remote debugging port 9223, but the main process failed before creating
the `BrowserWindow`, so `/json/list` contained no renderer page. TypeScript
project references typechecked the import but did not make the source-only
workspace package executable from the emitted CommonJS main.

`scripts/build-builder-electron.mjs` now uses Builder's declared Vite version to
produce one CommonJS SSR bundle. It bundles `@himmelcad/app` and keeps Electron,
`electron-updater`, and the automation host's real CommonJS runtime entries
external. Builder's development and production build scripts both use this
path. `scripts/test-builder-electron-build.mjs` builds to an owned temporary
directory and asserts that `JobRegistry` is bundled, no runtime
`require("@himmelcad/app")` remains, and Electron remains external.

With the main process running, the renderer initially remained blank and
reported React's `The result of getSnapshot should be cached` warning followed
by an uncaught `Maximum update depth exceeded` error in `<App>`. The P9 display
store violated `useSyncExternalStore`'s identity contract. It now returns one
cached snapshot and replaces that snapshot only in `changed()`, before
notifying subscribers. The app test asserts stable identity between
notifications and a new stable identity after a display edit.

After both fixes, a fresh normal launch staged the current dev WASM in 1 minute
25 seconds under load, brought Vite up in 331 ms, built the Electron main in
1.07 seconds, created the renderer target, mounted the complete shell, and
exposed `window.__hcadBuilderKernel.session`. Main-process output contained no
error. A diagnostic renderer reload produced no `console.error`, warning, or
`pageerror`; it did report one `net::ERR_ABORTED` request because the reload
cancelled an in-flight range request for the persisted project. The reloaded
page recovered, rendered the cloud, and kept the kernel available.

The actual Electron page capture is
`.build/perf/builder-window-2026-09-06.png` (1787×1040). It shows the Builder
title/ribbon, tree, Properties island, viewport, 3D/2.5D/2D controls, console,
status bar, and a rendered point cloud rather than a white or blank window.

## Harness attachment and lifecycle

The target URL filter (`localhost` or `127.0.0.1` on port 5173) and placement of
`--remote-debugging-port=9223` were correct. The missing page was a consequence
of the main-process module failure, not a target created before attachment, a
GPU-adapter wait, or a hidden second Electron instance.

The harness changes make the failure boundaries explicit:

- The normal Builder launch runs in an owned Unix process group. Shutdown sends
  `SIGTERM`, waits up to five seconds, then uses `SIGKILL` only if that exact
  owned group remains. It happens before the bounded CDP close, fixing the
  former `browser.close()`-before-child-cleanup hang.
- A child exit by status or signal now fails immediately. A missing renderer
  reports observed page URLs plus the retained Builder output tail.
- The pre-CDP allowance is 15 minutes because normal startup includes the
  serialized Rust/WASM build and may wait behind another `target/builder`
  owner. Renderer-target and kernel attachment remain independently bounded at
  120 seconds.
- Auto-launch uses a fresh temporary Electron user-data directory, passed by
  `scripts/run-electron.mjs`, so a previously open project cannot contribute
  residency or fetch work to the benchmark. The exact directory is removed
  after shutdown. `--no-launch` intentionally retains the caller's profile.
- The existing rejection of `deviceKind: cpu`, SwiftShader, llvmpipe, and
  software rasterizers is unchanged.

One pre-CDP invocation encountered S-08b's live Cargo lock and produced no
frames before the old 240-second startup allowance elapsed. That exposed the
startup-bound defect above; the final report overwrites that blocked artifact.
The one numeric capture below ran only after all Builder/viewer lanes had
finished. Afterward, ports 5173/9223 were closed, no owned Builder process
remained, and no `hcad-viewer-baseline-*` temporary profile remained.
