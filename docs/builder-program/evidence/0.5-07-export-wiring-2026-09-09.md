Date: 2026-09-09

## Outcome

Builder now exposes the one generated `entity.export` act as **File ▸ Export…** and as the existing product-aware tree/entity context command. It opens a 480 px File-owned export island docked on the right and detachable to a draggable island. The island provides:

- the five registered export families (DXF, LandXML, IFC, GeoTIFF, and splat), with inapplicable choices disabled and an explanatory tooltip;
- Selection, Visible, and Project scopes, with Visible selected when there is no exportable selection;
- an Electron main-process OS save dialog and a monospaced target-path display;
- an explicit `io.export.plan` review table with entity kind, count, target representation, every provider loss code, plain-English loss/CRS/provenance notes, and raw loss codes in the tooltip;
- an Export button that is unavailable until a plan exists, plus provider phase/progress and cancellation through the S-05 main-process job registry;
- completion/failure/cancellation console lines and the S-05 completion toast's **Show in folder** action.

`io.export.plan` now accepts exact user-level entity IDs for Selection/Visible/Project rather than treating an import command ID as scope. Its accepted envelope freezes every selected canonical entity version. `io.export.execute` reconstructs the live scope and refuses a stale plan before writing. Authored points/curves/measurements and imported products can share a scope. Resource-backed 0.5-05 TINs are resolved from their authoritative `hcad.section-topology-index@2` artifacts for the existing DXF/LandXML exporters; the 0.5-06 lane was still in flight, so its editing implementation was consumed through that same immutable prepared-TIN contract and was not edited here.

The existing providers retain ownership of output semantics and atomic publication. DXF now writes an `ElevationSurface::Tin` as 3DFACE records plus its breaklines. LandXML execute now enforces the same accepted-loss-code review already required by the other lossy exporters. No second exporter or parallel public command table was added.

## P11 / S-06d / S-05 trace

- `entity.export` remains the single generated public command row. The File ribbon and S-06d context menu dispatch that row to the same island; generated console completion/dispatch and the Python SDK continue to derive from the same row.
- The island uses the existing typed `IoClient` methods and existing `io.formats.page`, `io.export.plan`, `io.export.execute`, and `io.operation.status/cancel` sidecar methods. These internal provider operations were extended for user scope; they were not duplicated as another UI-only command family.
- Execute registers `owner: builder.export` with the S-05 registry before the sidecar call. The registry owns cancellation and forwards it once to `io.operation.cancel`; provider completion/failure/cancellation closes the matching job lifecycle.

## Round-trip and loss gates

### DXF road DGM + breakline

`dxf_provider::tests::road_dgm_export_round_trip_through_dxf_within_tolerance` imports a small road TIN with two faces and a crown breakline, plans and accepts its DXF losses, exports atomically, re-imports the DXF, canonicalizes triangle vertex ordering, and compares every X/Y/Z triangle and breakline coordinate at `1e-9`. It also proves the TIN is not reported as an omitted entity.

### LandXML import → export → re-import

No Brandenburg LandXML fixture was found under the repository or `.build` (`rg --files . .build | rg -i 'brandenburg|landxml|\\.xml$'`; the XML results were OpenCV/GDAL/build metadata only). Therefore **G-MT-5 Brandenburg is NOT RUN — fixture unavailable**.

The required fallback is covered by the synthetic civil fixture in `landxml::tests::export_plan_roundtrips_supported_civil_geometry_and_declares_omissions`. It imports LandXML, refuses execute before all plan losses are accepted, exports, re-imports, and compares the complete inline TIN positions, indices, and breakline geometry for equality. This is the synthetic-format fidelity gate, not evidence for Brandenburg-specific source data.

### Plan-loss parity

`apps/builder/test/exportDisclosure.test.ts` models a DXF scope containing a road Surface, saved Measurement, and PointCloud. The table reports Surface → `3DFACE + breaklines`, Measurement/Point Cloud → `not written`, and asserts that the union of displayed raw codes equals the provider plan's code set with no invented code. Provider-derived metadata notes explicitly disclose CRS metadata, recipes, and provenance dropped by DXF.

### Cancellation / atomicity

`landxml::tests::cancelled_export_leaves_no_target_or_staging_file` cancels during provider work and asserts that neither the target nor the hidden staging file exists. `canonical_provider::tests::registry_export_requires_plan_parity_and_observes_cancellation` covers registry-level plan equality and cancellation. DXF and the passthrough providers continue to write a sibling temporary file and publish only by atomic rename.

## Deliberate limits / follow-up

- Exact IFC, GeoTIFF, and splat export remains source passthrough only. The island explains that constraint and the provider plan remains the final authority; it does not imply a synthetic writer.
- A newly authored or derived TIN with no authoritative unit/CRS provenance cannot be exported as LandXML until the user supplies that truth through a future format-options UI. The provider continues to fail closed rather than inventing units or a CRS. A DGM scope that includes its LandXML-origin breakline/source carries the existing import document metadata and exports normally.
- The export capture currently materializes a resource-backed TIN into in-memory canonical vectors before invoking the existing writers. A bounded/streamed very-large edited-TIN export path is follow-up renderer/I/O work; exact CAS topology remains authoritative throughout this implementation.
