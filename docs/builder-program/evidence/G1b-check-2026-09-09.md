# G1b literal-UI check — 2026-09-09

Result: **FAIL — G1b does not close the G1c matrix.** The sparse and dense
`potree@2` snapshots import and render, preserve their frozen Lineage, and are
idempotent. Both prepared DEM snapshots fail before admission with `prepared
dataset binding differs from canonical geometry`. The strict render and pick
criteria also lack the required PhotoLab-side visual/pick oracle in the supplied
smoke evidence. Dense point snapping passes; sparse point snapping does not.

This was a one-pass verification of landed G1b commit `437789f` on its current
descendant `6a903a9` (the intervening runtime diff is a sidecar benchmark/Cargo
registration, not the G1b import path). No product code or fixture was changed
and no commit was made. All fixture reads were from the
requested `.build/photolab-e2e/**/.photolab/product-import-packages/` paths.
Builder wrote only its fresh test project/profile under `.build/g1b-check/`.

## Method and environment

The literal route was used for every attempt: **File ribbon → Import… → PhotoLab
product dataset → native directory chooser → chooser row → Import**. Builder was
driven through its Electron CDP endpoint on `DISPLAY=:0`, following V-01b. The
bundled in-app Browser reported that no browser was available, so it could not
attach; CDP and X11 keyboard input were used only to operate the visible Builder
and native chooser. No preload API or sidecar import command was called directly.

The first fresh launch exposed a stale debug sidecar (`measurement.list: method
not found`). I rebuilt the already-landed sidecar with
`CARGO_TARGET_DIR=target/builder node scripts/run-cargo.mjs build -p
himmelcad-sidecar --bin himmelcad-sidecar` (success, 1 min 42 s, two existing
warnings), retained that failed profile as `.build/g1b-check/profile-stale-sidecar/`,
and restarted with a clean `.build/g1b-check/profile/`. This rebuilt binaries but
did not change source.

1 GiB. If the package's “free memory” instruction intended that literal column
rather than available memory, the run should have been refused; this distinction
is recorded rather than hidden.

The final test project is 1.3 GiB and contains two imported dataset records
([dataset inventory](../../../.build/g1b-check/logs/datasets-final.txt)), 20 CAS

journal entries ([journal inventory](../../../.build/g1b-check/logs/journal-final.txt)).

`package_sha256`, serialized recursively with UTF-8 byte-sorted keys and no
whitespace (the canonical algorithm in `canonical_json.rs`), and SHA-256 hashed
the result. All declared/computed pairs match; see

## Defects / exact reproductions

1. **Builder DEM admission failure:** on either Ready DEM chooser row, press
   Import; after verification/progress, the sidecar returns `prepared dataset
   binding differs from canonical geometry` and no DEM row is created.
2. **Post-commit modal stack:** import either point package; after the success
   message, the PhotoLab chooser remains open over a generic registration Import
   island showing the package as `Not imported`. Manually close both to see the
   already-rendered cloud.
3. **Undo/redo surface is a placeholder:** import a point package, click the
   visible File-ribbon Undo (or Ctrl+Z); `project.undo` opens as an unshipped
   Function and the row remains. Redo behaves the same way.
4. **Sparse snap missing:** with sparse as the only visible cloud, choose Draw →
   Line and click a HUD-resolved point; status remains `Snap: —`, vertices remain
   zero. Dense at the analogous route returns `Snap: Point`.
5. **Dense progress overload:** import the 1.24 GB package. While progress events
   are delivered, renderer RSS climbs past 3 GiB by completion, CPU stays near a
   full core, and CDP stops servicing basic UI queries/screenshots. Backlog and
   RSS continue growing after the success notification.
6. **PhotoLab comparison oracle absent:** neither supplied smoke `result.json`
   nor the fixture trees contain the reference camera/screenshot or pick
   coordinates required by the matrix's render/pick criteria.
7. **DTM lineage is not DTM/SMRF:** inspect `product-60af8cb2…/objects/lineage.json`;
   it declares `all_imported_cameras`, with no SMRF identity, just like DSM.
8. **Reload diagnostic:** after dense commit/restart, Builder reports a nonfatal
   canonical-residency error for sparse: its viewer `datasetId is already
   registered`. Both cloud rows nevertheless restore and render.
