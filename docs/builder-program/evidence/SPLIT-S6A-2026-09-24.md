# Split step 6a — per-domain route registration

Date: 2026-09-24

Scope: remove the legacy central dispatcher without changing protocol bytes. This
step deliberately keeps one sidecar binary; product-specific binaries are step
6b.

## Result

The sidecar now builds one exact-method `RpcModule` per frozen handler family.
`build_command_registry(selection)` registers the shared set first and then the
selected Builder and PhotoLab sets. The current process selects both products,
so the externally visible route set remains all 163 methods. Duplicate exact
methods still fail registry construction and therefore process start-up.

There is no legacy module, prefix fallback, central method match, or text-scan
inventory. Unknown methods are rejected by the host after an exact registry
miss with the existing `-32601` response. The registered inventory, including
every `product` value, equals `tests/golden/route-inventory.json` exactly.

## Context split

The nine-service `LegacyContext` was deleted. The registry context type is now
`()`: each registered closure captures its module's narrow context.

- Shared: automation receives automation plus canonical-app state; canonical
  app receives canonical-app plus automation state; generic I/O receives its
  operation tracker plus canonical-app state; registration receives its
  runtime plus canonical-app state.
- Builder: archive receives I/O operations plus canonical-app state; mesh,
  ground, processing and segment each receive ground-operation coordination
  plus canonical-app state; Builder root receives only LAS-import coordination
  plus canonical-app state.
- PhotoLab: capture, HimmelCap and products receive the project runtime; CRS
  receives only the CRS service; images and GCP receive project plus CRS;
  project receives project plus jobs; jobs receives jobs, project and CRS;
  PhotoLab root receives project plus jobs.

No Builder route module receives the PhotoLab project, job or CRS runtimes.
`RouteServices` is the composition input at process start-up, not a handler
context.

## Frozen protocol and corpus

`--list-routes` equals the golden exactly for method, handler family and product
classification. The text parser and its inventory test were deleted. The
replacement `registered_route_products_match_golden` test explicitly freezes
the method-to-product mapping independently of the full inventory assertion.

All 37 differential fixtures replayed byte-for-byte. Existing success fixtures
already exercise 17 of the 18 families. Automation remains the documented
exception: deterministic success needs canonical document/operation state;
its handler signature was not changed and its invalid response remains frozen.
No new response fixture was therefore needed.
