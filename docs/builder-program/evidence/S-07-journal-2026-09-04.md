# S-07 — journal group commit and durability indicator

Date: 2026-09-04

## Outcome

Builder ordinary canonical transactions now stage without an fsync on the request path and cross a grouped durability boundary after a tunable interval (`HCAD_JOURNAL_FLUSH_INTERVAL_MS`, default 50 ms). The sidecar reports visible and durable generations separately. A failed flush leaves the tail queued, rejects later canonical edits, and clears only after a successful retry.

The renderer shows only the acknowledged states `Stored`, `Storing…`, or `Not stored — <reason>`. The failure toast names that changes remain queued and exposes `Retry`. Ctrl+S and the existing ribbon Save position dispatch `project.flush`; that operation first retries/drains pending work, appends a manual `hcad.snapshot-marker@1` marker, and returns only after the marker is durable. Successful open adds and durably flushes one automatic `Session start` marker before returning the document snapshot.

## Concurrency and recovery

- Canonical mutation acceptance remains serialized by the existing canonical runtime mutex. Multiple accepted ordinary commands inside the interval share one flush; redundant timer wakes are harmless.
- Synchronous import/publication paths drain pending ordinary commands first. A prior durability failure rejects them rather than allowing an unjournaled or falsely acknowledged state.
- The ready marker is synchronized before journal publication. Reopen completes a staged tail, counts it, and the renderer reports the recovery. A malformed/truncated journal still fails open; it is never skipped.
- Normal close flushes before releasing the project lock. A failed close-time flush keeps the project open and returns `closed: false`.
- Ordinary journal flush is bounded and intentionally not a cancellable long job. Heavy import/archive work stays on its existing background-job lifecycle.

## S-07b — snapshot bookkeeping, retention, and restore (2026-09-08)

### Outcome

- `hcad.snapshot-marker@1` remains canonical project bookkeeping but is excluded
  before Builder constructs its scene/entity-tree projection. A focused
  projection test proves that neither the marker nor a parent/child edge for it
  reaches `EntityTree`.
- Session-start creation now detects an unchanged session and emits no marker.
  The default per-project retention is the five newest session-start markers,
  tunable with `HCAD_SESSION_START_SNAPSHOT_RETENTION`; manual snapshots are
  untouched. Creation/eviction and legacy compaction each publish as one
  journaled bookkeeping transaction. Open reports, for example,
  `Compacted 35 session-start snapshots to 5` to sidecar stderr, which Builder
  forwards to its console.
- `snapshot.restore` now has a sidecar RPC implementation shared by UI and
  automation. It reconstructs the marked journal generation, appends one
  forward compensating command for all non-snapshot canonical state, and adds a
  linked `Before restoring '<name>'` safety marker. Snapshot markers are the
  only restore exemption; the journal never rewinds.
- File ribbon now places **Snapshots ▾** beside Save. Its newest-first 28 px rows
  show a 13 px name and muted monospaced time/generation; hover/focus reveals an
  inline secondary **Restore** button. Both the row and inline action open the
  S-02 destructive confirmation dialog with the consequence copy. Successful
  restore refreshes the canonical projection, residency, list, and console.
- Gallery section **Snapshots menu** covers the list and confirmation dialog.
  The serial gallery run captured 80 screenshots for 39 sections; the new light
  and dark images were visually inspected at
  `packages/@himmelcad/ui/gallery/shots/{light,dark}/snapshots-menu.png`.
