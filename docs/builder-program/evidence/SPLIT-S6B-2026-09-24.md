# Split step 6b — product sidecars and packaging

Date: 2026-09-24

## Outcome

The sidecar is now composed without Cargo product features:

- `himmelcad-sidecar` is a library containing the shared stdio host, exact command registry integration, shared route families, and shared runtime adapters. It no longer builds the transitional all-products `himmelcad-sidecar` binary.
- `himmelcad-builder-sidecar` is a product-layer binary crate. It owns Builder route modules plus the Builder-only drafting and surface adapters.
- `himmelcad-photolab-sidecar` is a product-layer package. It owns the PhotoLab route modules, PhotoLab runtime adapters, the `himmelcad-photolab-sidecar` binary, and the PhotoLab-only `himmelcad-portable-mvs` binary. Its small library target exposes the PhotoLab-only prepared-triangle-mesh implementation to its existing example and tests without compiling that implementation twice.

This is the smallest structure that keeps route source code in packages selected by one product binary: extra `*-routes` packages would add package boundaries without improving dependency isolation. The shared host receives an exact registry, route metadata, canonical runtime, and product lifecycle implementation from the selected binary.

There are no Cargo features selecting route sets, no package renames, no cross-crate `include!`, no self aliases, and no exported domain macros. There is no old all-products binary or unswitched source consumer left.

## Helper and ownership distribution

- Shared: JSON-RPC request/response types, exact shared registration, common blocking/result/error adapters, progress coalescing, stdio transport, shutdown dispatch, automation, application negotiation, generic IO, registration, and shared root routes remain in `himmelcad-sidecar`.
- Builder: archive, point-cloud ground/processing/segmentation, mesh-surface, document-history, drafting, viewing-box, measurement, drawing, snapshot, and Builder root helpers live in `himmelcad-builder-sidecar`. A local `SurfaceRuntimeAdapter` satisfies Rust's orphan rules while keeping the canonical runtime shared.
- PhotoLab: capture, CRS, GCP, HimmelCap, image, job, product, project, alignment/batch/product orchestration, dense raster, mesh/texture, export, splat, and hardware helpers live in `himmelcad-photolab-sidecar`.
- Domain logic: the worker-toolchain policy moved from `himmelcad-command` into its owner, `himmelcad-domain-photogrammetry`; the obsolete command-layer job-runtime re-export was removed. Wire shapes and algorithms were not changed.
- Tests moved with their owners: shared progress/negotiation/IO tests to the shared host/routes, Builder segmentation/history/LAS tests to Builder, and PhotoLab tests with PhotoLab.

## Normal dependency closures

`cargo tree -e normal` proves the product boundary rather than relying on feature unification:

- Builder links `himmelcad-domain-drafting`, `himmelcad-domain-pointcloud`, and `himmelcad-domain-surface` for its product routes, plus `himmelcad-domain-registration` through the shared registration routes. It links the shared command/foundation crates. It does **not** link `himmelcad-domain-photogrammetry` or `himmelcad-domain-raster`.
- PhotoLab links `himmelcad-domain-photogrammetry`, `himmelcad-domain-raster`, and `himmelcad-domain-pointcloud` for PhotoLab processing/product routes, plus `himmelcad-domain-registration` through the shared registration routes. It links the shared command/foundation crates. It does **not** link `himmelcad-domain-drafting` or `himmelcad-domain-surface`. `himmelcad-render` is a PhotoLab test-only dependency, not a normal dependency.
