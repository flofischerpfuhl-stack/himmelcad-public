# Split step 2 — command registry seam

Date: 2026-09-23
Scope: ADR 0032 split step 2 only. No route family moved and no request,
response, error, default, serialization, schema, or algorithm changed.

## Design

`himmelcad-command` is a dependency-free command-layer crate. Its
`CommandRegistry<Context, Request, Response>` owns a lexically ordered map of
exact `&'static str` methods to `Send + Sync` handlers returning
`Pin<Box<dyn Future<Output = Response> + Send + 'static>>`. The request,
response, and context types are generic, so the crate neither defines nor
depends on JSON-RPC wire types or sidecar state. `RpcModule::register` receives
the typed registry. A second registration of the same exact method returns
`DuplicateMethod`; normal sidecar startup constructs the registry with `?`, so
a duplicate fails startup.

The private `LegacyContext` contains exactly the nine services already passed
to the old `handle` function: project, jobs, CRS, LAS import, ground/mesh,
generic I/O, registration, automation, and canonical-app runtimes. No state
type moved crates.

`LegacyRpcModule` registers all 163 frozen methods in lexical order. Every
entry calls `handle_with_context`, which delegates to the existing `handle`
function. Thus today's prefix tests and 13 `match` blocks remain in place as
one legacy module; there is no registered prefix fallback. For an unregistered
method, `CommandRegistry::dispatch` returns the untouched request and context,
and the host calls the same legacy `handle` function. This deliberately
preserves both the prefix-family unknown paths and the root `-32601` response.
The parser, spawn/concurrency behavior, error mapping, response channel,
`serde_json::to_string`, newline, flush, and stdout writer are unchanged.

`himmelcad-sidecar --list-routes` builds the same registry without constructing
runtime services, emits one JSON inventory, and exits. Normal startup receives
no new stdout. The frozen test now independently checks (1) the step-1 text
scan of `main.rs` and (2) this registry inventory against the same
`route-inventory.json` golden. Later route moves can delete only the text scan.

The registry table is explicit source, not linker inventory. There are no new
external dependencies. `himmelcad-command` and `himmelcad-sidecar` are both in
the `command` layer, so `himmelcad-sidecar -> himmelcad-command` is a permitted
command-to-command edge and the dependency allowlist remains unchanged at
eight entries.

The lifecycle project is created only below `.build/split-s2/`, requests are
sent one at a time after receiving the preceding response, and the test removes
the project afterward. Together with the pre-existing `root-ping`, successful
fixtures exercise 17 of 18 handler families. `automation` has no success
fixture: its deterministic successful reads require an open canonical Builder
document, and its status/cancel/bulk success paths require a previously created
operation or lease. Those prerequisites are not created by any side-effect-free
transport route. Its exact invalid response remains frozen.

Environment probes are intentionally not golden successes:
`photolab.capture.capabilities`, `photolab.hardware.probe`, and CRS discovery
depend on installed tools, hardware, or the local PROJ database. Registration
state/resource queries require a staged source dataset. Generic I/O operation
status requires a live operation. All deterministic list/query routes available
from a new PhotoLab project are included in the lifecycle fixture.

Normalization is per fixture and limited as follows:

- `canonical-app-negotiate-success`: replace only `result.sessionId`, which
  embeds the sidecar process id, with `<session-id>`; all remaining wire bytes
  compare directly.
- `photolab-project-lifecycle-success`: replace only the scratch absolute path,
  generated project and session ids, `createdUnixMs`, `modifiedUnixMs`, and the
  five initial entity version hashes derived from those generated values. The
  SHA-256 of every remaining raw response byte, including field order and line
  framing, must equal
  `f58ce4dd97a7fb4ac1a78572aedec3110c2a4487ac15877bde0f6fd9aa033921`.
- Every other fixture has no normalization and compares stdout byte-for-byte,
  including the existing unknown-method `-32601` response.
