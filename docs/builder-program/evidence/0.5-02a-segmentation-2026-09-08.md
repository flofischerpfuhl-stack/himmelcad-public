# 0.5-02a — point-cloud fence segmentation evidence (2026-09-08)

## Outcome

This work package implements the Release 0.5 point-cloud segmentation slice as an immutable prepared-dataset edit. A deliberately selected set of editable, rendered point clouds is captured with its P4-visible classifications and active viewing-box scope. The armed viewport tool draws a rectangle or polygon and freezes it as a camera-free PC-D5 volume: an orthographic prism, perspective eye-apex frustum, or typed box. **Keep inside** and **Remove inside** are the symmetric X5 pair.

The bake reads one bounded Potree node at a time, writes a native `potree@2` dataset, and publishes every selected cloud's next revision in one canonical transaction. The source revision remains journal truth; undo restores its representation and component/attribute references. Repeated segmentation consumes the current revision and appends `hcad.pointcloud.segment@1` recipes to `hcad.point-cloud-edit-chain@1`.

## Delivered surfaces and contracts

- `packages/@himmelcad/viewer/src/kernel/KernelFenceVolume.ts`: shared projection-true prism/frustum/box construction, validation, area, and membership math. Perspective tests probe the same screen fence at multiple depths; an explicitly typed world polygon becomes a camera-free orthographic prism, while perspective automation supplies the complete apex frustum. Oblique prism directions and rotated boxes are covered separately.
- `apps/builder/renderer/src/BuilderKernelViewport.tsx`: S-03 armed LMB rectangle/polygon interaction; first-vertex closure hover; double-click/Enter close; Ctrl+Z vertex/reopen behavior; Escape at the tool rung; camera gestures are rejected while an open fence would otherwise change its plane. Arbiter claims stay stable through rectangle drag updates and re-arm after Escape discards a fence. The overlay uses a 1.5 px dashed accent line and 6 px support-blue vertex squares while drawing, then an 8% accent fill with solid outline.
- `apps/builder/renderer/src/PointcloudSegmentPanel.tsx`: docked Segment panel with mode choice, vertex count and area, equal-width primary **Keep inside** and neutral secondary **Remove inside**, quiet **Clear fence**, and the S-05 progress/cancel row.
- `packages/@himmelcad/app/src/constructionInput.ts`: semantic field labels allow the shared construction bar to expose exact rectangle **Width** and **Height** without a second input owner.
- `crates/himmelcad-sidecar/src/pointcloud_segment.rs`: bounded scan/bake, P4 classification/viewing-box scope, symmetric keep/remove membership, deterministic recipe membership hash, phase cancellation, a native hierarchy pruned to retained branches, camelCase typed-box wire parity, and a 104 M-point ignored operational gate.
- `crates/himmelcad-sidecar/src/canonical_app_runtime.rs`: atomic multi-cloud revision publication, exact CAS inputs, formal P10 recipe, edit-chain append, cancellation before publication, and standard journal undo.
- `schemas/automation/himmelcad-automation-v1.schema.json`: P11 rows `pointcloud.fence.begin/commit/cancel` and `pointcloud.segment.keep_inside/remove_inside`, all carrying `owner: pointcloud`. The typed S-01 request admits a polygon or a complete camera-free prism/frustum/box.
- `apps/builder/electron/main.ts`: registered job cancellation routes to `pointcloud.segment.cancel`. A newer request for the same entity set cancels and waits for the previous request before registration, bounding the per-entity edit queue to one.
- `packages/@himmelcad/ui/gallery/Gallery.tsx`: **Segment panel** drawing, closed-fence, and baking states.
- `packages/@himmelcad/theme/src/tokens.css`: supplies the shared 4/8/12 px panel spacing scale already consumed by the ground, sampling, and segmentation panels; without it their declared gaps and padding collapsed.
- `scripts/verify-pointcloud-segmentation.mjs`: repeatable small-suite entry and opt-in `--real-data` 104 M-point scan/bake/cancellation gate using the prepared viewer fixture.

No 0.5-01 viewing-box kernel/coordinator source and no V-05 render-crate source was edited by this work package. The segmentation implementation consumes the current viewing-box state and current viewer public boundary.

## Traceability and limits

`G-PC-A`…`G-PC-E` are broad point-cloud gates. This evidence claims only their fence subset: exact projection volume, visible-class/viewing-box scope, symmetric in/out membership, immutable native rebake, journal undo, and cancellation. It does not claim unrelated registration, classification, selection, or display portions of those gates.

The missing `G-RW-SEGMENT` definition and the renderer-conditioned alpha seam are recorded rather than silently treated as passes. The 104 M-point test and performance comparison remain necessary before the Release 0.5 segmentation gate can be called closed.
