## Repairs

### DEM admission and publication validation

The original `prepared dataset binding differs from canonical geometry` failure was a Builder importer defect. A PhotoLab package artifact describes `dataset/viewer/manifest.json` as transport MIME `application/json`, while the canonical Grid geometry binds its root as the semantic format `himmelcad-prepared-hierarchy@1`. Builder copied the transport MIME into `CanonicalPreparedDataset.root_metadata`; canonical admission correctly rejected that disagreement. The importer now uses the semantic format for a prepared-hierarchy root and preserves transport MIME for the other immutable artifacts.

That correction allowed both DEM fixtures through the original binding check and exposed a separate PhotoLab publication defect before commit. Builder now validates that every Raster tile's `bitsetLsb0` decoder band has exactly `ceil(width × height / 8)` bytes. The regression tests are:

- `prepared_hierarchy_root_uses_semantic_format_not_transport_mime`
- `landed_dsm_and_dtm_refuse_global_validity_as_a_tile_decoder_band`

### Journaled product import

`project.undo` and `project.redo` are canonical sidecar methods, generated Builder commands, Edit-ribbon actions, console/automation commands, and Python SDK commands. The runtime selects the preceding journal root while skipping snapshot-only markers. Undo removes the imported entity and its dataset residency registration; the immutable CAS object remains. Redo restores the same entity and dataset, including after close/reopen, and reuses the retained CAS object.

The viewer reconciliation hides a document-removed entity while the sidecar removes its canonical dataset registration, retains already-decoded bytes as a presentation cache, and skips that already-resident cache when applying the refreshed bootstrap. Redo restores the canonical row and its prior visibility without attempting a conflicting second viewer admission. Regression coverage is in `photolab_product_import_is_idempotent_and_copies_package_payload_to_cas` and `document_history_methods_route_to_the_canonical_runtime`.

### Sparse cloud snapping

Sparse and dense package metadata both publish point spacing, and the sparse cloud was not excluded from the snap lane. The failure was the navigation controller's hard-coded 4-physical-pixel geometry pick radius: the visible sparse feature lay outside that neighborhood, while the dense cloud happened to populate it. Hover and click now use the viewer contract's bounded 8-pixel geometry lane. `sparse-cloud hover acquisition uses the bounded eight-pixel geometry lane` supplies a candidate only at radius 7 and verifies acquisition with radius 8.

### Typed import failures

Electron preserves the S-01 product refusal `{reasonCode, message}` through a bounded encoded marker even when `invoke` serializes the rejection as a plain `Error`. The island parses only the closed product-import reason codes. Unknown exceptions and raw `SidecarRpcError` strings become the generic `product_import_failed_no_commit` sentence and cannot appear in the modal. Builder tests cover both the typed wrapper and raw-RPC sanitization.

Selected imported DEMs would expose semantics, interpolation, connectivity/diagonal, authoritative validity encoding/resource ratio, and source NoData in Lineage. The supplied DEMs cannot reach that UI because their authoritative decoder inputs are inconsistent; Builder does not invent a mask to make them render.

## DEM publication finding

IF-D19–IF-D25 make the published package authoritative, and the Raster decoder requires one LSB-first validity bit per tile pixel. Both fixture hierarchies describe every tile as `width=512`, `height=512`, so each tile decoder band must contain `32,768` bytes. Instead, every checked tile at L00, L01, and L02 has:

```text
validityReference.byteOffset = null
validityReference.byteLength = 524288
validityReference.uri = ../../../../validity.bin
```

The 524,288-byte object is the full 2048×2048 base-grid validity bitset. It cannot be interpreted as a 512×512 tile band, and the coarser L01/L02 masks cannot be authoritatively derived from it because the package supplies neither per-tile resources nor a window/downsampling contract.

Exact differing identities:

| Fixture | `dem_facts.validity.resource.sha256` and every tile `contentHash` | Observed / required tile bytes | Source NoData |
| --- | --- | ---: | --- |
| DSM `product-e288ad8f…` | `e51739bedbf7c91c33e908b05562cbbb28736f50530883116f3a03be776e7f43` | 524,288 / 32,768 | numeric `-340282346638528860000000000000000000000` |
| DTM `product-60af8cb2…` | `dbff5b8beae260697004f86addbe98c427f4bad2e988841e4453cab9414c7eae` | 524,288 / 32,768 | numeric `-340282346638528860000000000000000000000` |

The two literal imports now stop before document/CAS mutation with reason code `invalid_package` and this user-readable sentence:

> The import package is invalid. Republish or recompute this product in PhotoLab. DEM tile validityReference.byteLength=524288 disagrees with decoder width=512, height=512; expected byteLength=32768 for one bitsetLsb0 bit per tile pixel.
