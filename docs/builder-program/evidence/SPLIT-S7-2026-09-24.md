# SPLIT S7 — hardware profile and truthful rendering status

Date: 2026-09-24
Scope: one foundation hardware-profile module in Rust and TypeScript; no budget,
threshold, backend-order, retry-count, or quality-governor behavior change.

## Result

The hardware decisions now have one foundation owner per language:

- `himmelcad-hardware-profile` owns portable render/compute identity,
  observations, budgets, policy/governor, deterministic quirks, and native
  probing behind `cfg(not(target_arch = "wasm32"))`.
- `@himmelcad/hardware-profile` owns the pure Electron switch policy, the
  unchanged persisted recovery ladder, quirk validation/order, and the
  user-visible rendering truth function.
- `himmelcad-render` retains the GPU calibration benchmark runner and consumes
  the profile's calibration/policy types.
- Builder and PhotoLab both pass injected Chromium and viewer facts into the
  same status derivation. Builder's existing chip and PhotoLab's existing
  status bar show the resulting label.

Native probing stays in the same Rust crate rather than a companion crate.
The implementation uses only `std` process/filesystem facilities and is
excluded from WASM at the module boundary, so another package would add an
edge without removing a dependency from the display closure.

## Quirks v1

The sole authored registry is
`packages/@himmelcad/hardware-profile/quirks-v1.json`. It currently contains
zero active rules, so this split adds no device-specific behavior.

Each rule has:

```text
{ id, priority,
  match: { os, vendorId, deviceId, driverMin, driverMax, backend,
           sessionType, electronRange },
  actions: { disableBackends, forceAngle, renderBudgetScale,
             computeBudgetScale },
  reason, expires }
```

Validation rejects unknown fields (including GPU-name matching), malformed or
duplicate stable ids, non-integer PCI ids, reversed dotted-numeric driver
ranges, scales outside `0.1..=1.0`, and incompatible equal-priority singular
actions. Resolution is priority descending, then stable id ascending; disabled
backends are de-duplicated and sorted, the highest-priority singular action
wins, and scales compose deterministically.

`scripts/generate-hardware-quirks.mjs` generates the owned Rust values in
`crates/himmelcad-hardware-profile/src/generated_quirks.rs`; `--check` is the
drift gate. It supports populated registries and never uses cross-crate
`include!`/`include_str!`.

## Rendering status truth table

| State/label         | Required facts                                                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Initializing`      | Viewer facts or Chromium feature facts have not arrived.                                                                                                 |
| `WebGPU (hardware)` | Viewer selected WebGPU, adapter explicitly reports `isFallbackAdapter: false`, and Chromium reports hardware-enabled GPU compositing, WebGL, and WebGPU. |
| `WebGL2 (hardware)` | Viewer selected WebGL2, adapter explicitly reports `isFallbackAdapter: false`, and Chromium reports hardware-enabled GPU compositing and WebGL.          |
| `Software`          | Persisted SwiftShader mode, viewer software mode, fallback adapter, or a required Chromium feature contains `software` or `readback`.                    |
| `Unavailable`       | Explicit failure, or required facts arrived but are not affirmatively hardware-enabled.                                                                  |

An enabled value must begin with `enabled` and must not contain `software` or
`readback`. Thus `disabled_software`, `enabled_readback`, and equivalent values
cannot produce a hardware label. The WIN-21/22 Vega 8 fixture
(`gpu_compositing=disabled_software`, `webgl=enabled_readback`,
`webgpu=disabled_software`) resolves to `Software` in a unit test.

  label in its existing status surface (`App.tsx:4000-4001`); no new UI surface
  was introduced.
- The viewer reports the selected backend plus the adapter fallback flag. In
  automatic mode a browser fallback adapter still routes to WebGL2; retry order
  and counts remain unchanged.
