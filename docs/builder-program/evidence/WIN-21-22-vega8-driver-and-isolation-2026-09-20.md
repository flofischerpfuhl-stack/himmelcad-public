# WIN-21 / WIN-21b / WIN-22 — Vega 8: driver update and isolation (DESKTOP-BNB2PBA), 2026-09-19/20

- **WIN-21:** AMD Adrenalin 26.5.2 WHQL installed from amd.com (signature verified), driver `31.0.12027.9001` → `31.0.21925.1001`, device OK, restore point created, old `oem47.inf` retained; PC rebooted (back on Tailscale after ~2 h).
- **WIN-21b:** acceptance FAILED with the new driver — 10/10 Builder launches log `GPU process exited unexpectedly: exit_code=34` (11 exits), nine recover with `gpu_compositing=disabled_software` / `webgl=enabled_readback`, one ends in terminal software fallback; the Builder chip still says "Hardware rendering" (untruthful status, Builder defect).
- **WIN-22 isolation:** the smallest failing case is **A — Electron 43.1.0 opening only `about:blank`** (4/5 launches exit 34, 5/5 end software/readback); plain WebGL2/WebGPU pages, Builder with forced WebGL2 and Builder default all fail too; Electron 42.11.6 also fails, 44.4.3 is worse. No `DXGI_ERROR_DEVICE_REMOVED`, no `DEVICE_HUNG`, no Dawn/ANGLE error, no Display event 4101. **HimmelCAD's viewer is not the cause.**

Open hypothesis (not tested — the week's Codex reserve is used): every launch in WIN-02…WIN-22 was started from an OpenSSH session, i.e. outside the interactive desktop session; a Chromium GPU process started that way may lose its context regardless of hardware. Deciding test: start Builder (or any Electron app / `chrome://gpu` in Chrome) from the logged-in desktop on the PC — by the owner, or by a brief that uses an interactive scheduled task (`schtasks /create /it`). If the desktop launch is clean, the Vega 8 finding is a test-method artifact and only the untruthful status chip remains as a defect.
