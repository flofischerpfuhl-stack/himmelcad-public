# SPLIT-S5D — document store, drafting domain, command automation

Date: 2026-09-24
Scope: module split only; no schema, serde, default, algorithm, file-format, wire, route, or user-visible behavior change.

## Result

Step 5d is implemented.

- The canonical project store now has one owner in `himmelcad-document`.
- The canonical import-package/provider publication contracts now have one owner in
  `himmelcad-document`; `himmelcad-io` re-exports them at the old paths.
- Drafting command logic now has one owner in the new
  `himmelcad-domain-drafting` domain crate.
- The bounded automation runtime now has one owner in `himmelcad-command`.
- The old sidecar module paths remain three-line compatibility facades.
- Route dispatch remains in the sidecar legacy registry/runtime, as required for
  the step-6 route move.

## Contracts moved down

The following definitions now exist only in
`himmelcad-document::canonical_import`:

- `CanonicalImportPackage`
- `CanonicalJsonObject`
- `CanonicalPreparedDataset`
- `CanonicalResourceSet`
- `PreparedDatasetArtifact`
- `PreparedResourceArtifact`
- `ProviderContractError`
- `CANONICAL_IO_SCHEMA_VERSION`
- their package validation and canonical transaction-construction helpers

They are document-level rather than model-level contracts because their closed
validation produces a `CanonicalCommandTransaction` and describes one atomic
publication into the canonical document. They are not provider execution or
format-decoding behavior. `himmelcad-io::canonical_provider` and
`himmelcad-io` keep public re-exports, so existing providers and consumers retain
their source paths.

No import-publication adapter had to remain in the sidecar. Providers still
prepare packages in IO/domain code; the journal-last filesystem publication is
document-store behavior and moved with the store. The moved store has no
`himmelcad-io` dependency.

The crash-safety implementation moved as a unit: write-ahead intent, staged
artifacts, ready marker, file/directory syncs, journal-last publication,
recovery/quarantine, durability failure lockout/retry, and group commit. The
store tests moved with it without scratch-path or timing-bound changes.

## Narrow injected traits

`himmelcad-document::domain_commands::DraftingDocumentCommands` exposes only:

- entity and tombstone reads;
- verified CAS object reads;
- canonical JSON/geometry object writes;
- canonical transaction append; and
- document undo/redo.

`CanonicalAppRuntime` implements the trait over `CanonicalProjectStore`.
`DraftingCommandService` owns bookmark, viewing-box, measurement, and
draw/construction validation, object construction/reading, transaction
construction, and undo/redo selection.

`himmelcad-command::automation_runtime::AutomationDocument` exposes only the
generation/entity snapshot, transaction validation, and a verified bounded CAS
source. `CanonicalAppRuntime` implements it. This keeps automation path-free and
command-layer-owned while document remains the authority for canonical state and
verified object handles.

## What stayed in `canonical_app_runtime.rs`, and why

The remaining production code is sidecar orchestration and adapter code:

- open/close/flush project lifecycle and process-local ownership;
- app-protocol snapshot, journal, property-edit, snapshot-marker, and generic
  document dispatch;
- provider registry import/export staging and residency reconstruction, which
  coordinate IO providers with the document store;
- sidecar process progress/cancellation and prepared-result publication;
- the concrete implementations of drafting, automation, point-cloud, and
  registration document traits; and
- compatibility wrappers that preserve the old runtime method signatures and
  error mapping used by legacy routes.

The file also retains sidecar integration tests which exercise reopen,
publication, and cross-domain orchestration through the public runtime. Route
matching, request decoding, and response serialization stay in `main.rs` and the
legacy route registry until step 6.

## Compatibility paths and consumers

- `himmelcad_sidecar::canonical_project_store::*` re-exports
  `himmelcad_document::canonical_project_store::*`. Current in-repository
  consumers are `canonical_app_runtime.rs` and `main.rs`, including progress,
  pinning, and materialization helpers.
- `himmelcad_sidecar::automation_runtime::*` re-exports
  `himmelcad_command::automation_runtime::*`. `main.rs` continues to import the
  old sidecar path.
- Drafting DTOs are re-exported by
  `himmelcad_sidecar::canonical_app_runtime`; `main.rs` currently consumes
  `DrawCurveInput` through that path.
- `himmelcad_io::{CanonicalImportPackage, CanonicalJsonObject,
CanonicalPreparedDataset, CanonicalResourceSet, ProviderContractError, ...}`
  remains valid. Current consumers include the sidecar, photogrammetry,
  registration, surface, and IO provider implementations/tests.

No executable script names either moved Rust source file literally. Existing
historical evidence and specification citations to the sidecar facade filenames
were not rewritten: the compatibility files still exist, and the task's read
boundary permitted only the named architecture/evidence inputs plus this new
evidence file.
