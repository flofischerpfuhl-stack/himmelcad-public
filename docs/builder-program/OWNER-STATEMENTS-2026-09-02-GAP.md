## 0. Audit basis and result

This audit applies the Builder-program rules in `README.md` §Rules: a plan is not evidence that code exists; a cited stub or deprecated surface is not existence; cross-spec capabilities require cite-and-revise on both sides; and the C1/P8/P9/P10 changes invalidate the previous “all fourteen specified” snapshot until every consumer has been re-walked. D7 explicitly un-defers Civil and assigns the receiving amendments (`OWNER-DECISIONS.md` D7, lines 162–180). The registry currently records only the earlier P5–P7 re-walk (`REGISTRY.md` §4, line 414 onward), so its “all specified” conclusion is stale.

During this audit `specs/civil/civil.md` was present as a new drafted fifteenth domain document. It is therefore assessed as the proposed Civil specification, not treated as missing. Its own header correctly says that its rows remain proposals until the architect registers them. The fourteen previously registered owning specs were read in full, as were the new Civil draft, `MASTER-PLAN.md`, and the requested dossiers. Two `*-spec-review-*` files were also read completely. The review lessons applied here are: a passive consumer is part of the contract; a heading or stub is not evidence; every gesture needs one arbitrated owner; extreme class members need gates; and catalog rows may not disappear silently.

### 0.2 Consequential gap-analysis decisions

#### GAP-D1 — Coverage is clause-level and planning status is kept separate from implementation

**Decision:** Count a clause as covered only when an owning specification gives workflow, command/state, failure, and verification intent. A doctrine precedent alone is “different/incomplete”; a model type, viewer hook, stub, or deprecated surface is not existence.  
**Derivation:** Function Contract A2/E3; Builder `README.md` Rules; Doctrine X1/X3/X7; the cited-stub rule in Function Contract lines 55–62.  
**Rejected:** counting a matching noun or data structure as a completed function; marking the whole statement covered when only one branch exists.  
**Tunable:** no.

#### GAP-D2 — Keep the shared construction bar; make Tab mean field traversal

**Decision:** S1's pending Cartesian/polar values and first-point coordinates belong in the persistent Draw construction bar, mirrored contextually in the function panel only when that panel owns additional options. Tab/Shift+Tab enters and traverses its fields without pointer motion; Up/Down cycles viewport candidates.  
**Derivation:** C1; X5/X7; `rib-civil.md` §2.2 F5/Tachobox; Draw DR-D1; the current catalog already advertises Up/Down at `ui-platform.md:43`.  
**Rejected:** moving common construction truth into every tool's right panel; retaining any Tab candidate-cycle branch. The shared bar is better than S1's literal panel placement because one persistent owner prevents tool-specific numeric-entry forks and leaves the right panel for function options.  
**Tunable:** exact field order and compact/expanded breakpoint.

#### GAP-D3 — P8 means four histories and four explicit paths, not four Ctrl+Z meanings

**Decision:** Ctrl+Z/Ctrl+Shift+Z remain document undo/redo. Selection, display/visibility, and camera each expose their own undo/redo controls and canonical query/actions; focus never silently reroutes Ctrl+Z.  
**Derivation:** P8; X3/X5; File FP-D10/FP-D11 document-journal ownership; current UIP-D3 separation at `ui-platform.md:602–609`.  
**Rejected:** one temporal mega-history; context-sensitive Ctrl+Z; UIP-D3's current “selection is not undoable” endpoint. The program form is better than the ambiguous owner phrase because every domain remains recoverable without making the principal shortcut unpredictable.  
**Tunable:** local history depth/coalescing and whether secondary undo is exposed by icon, menu, or both.

#### GAP-D4 — P9 is one composed effective interaction state

**Decision:** UI Platform owns the four-state control and propagation; Select/Edit owns the single effective-state resolver across entity, ancestor, layer, kind, cloud class, attached project, session isolate, and global overlays. Domain specs consume the result and never invent a second lock/visibility state.  
**Derivation:** P9; X1/X3/X7; Draw DR-D4; Select/Edit SE-D9; UIP-D18; owner decision D5.  
**Rejected:** independent booleans whose combinations disagree; mutating per-element choices when a global control changes.  
**Tunable:** iconography and initial defaults only.

#### GAP-D5 — Civil is a real domain but not a new ribbon tab

**Decision:** Adopt the live Civil draft's boundary and records CIV-D1–D14. Civil owns semantic alignments/profiles/corridors/slopes/pits; its functions remain grouped under Draw and hand off publication to Mesh.  
**Derivation:** D7; Civil §0/CIV-D10; owner decision D2's fixed tab taxonomy; X7.  
**Rejected:** leaving DR-D8 deferred; a second Civil surface creator; a new tab without an owner decision.  
**Tunable:** Draw group ordering.

#### GAP-D6 — Rigid sections and civil profiles are distinct products

**Decision:** View owns a live rigid section made from a selected line, direction, depth, arrowed specification, and exact rotated frame. Civil owns station/offset long and cross profiles, applying P10 to live mapped geometry and stale projected traces. Existing axis clip planes remain a separate View function.  
**Derivation:** P10; S8; View VD-D1; Civil §0/CIV-D7/CIV-D12; X1/X3.  
**Rejected:** renaming a clip plane to satisfy S8; giving all sections to Civil; blanket manual synchronization.  
**Tunable:** default depth, profile exaggeration, and refresh budget.

#### GAP-D7 — Extend the Mesh window; do not replace it with a popup

**Decision:** Retain MT-D1's dedicated, resizable, persistent surface workspace, source-local draft fixes, explicit roles, P4 capture, error navigation, checkpoint/restart, and one atomic publish. Add S10's form-line role, two rule exclusions, two mean-height samplers, and in-window 2D crop construction.  
**Derivation:** B3; P4/P5; S10/G10; MT-D1–D5/MT-D16/MT-D17; X1/X2.  
**Rejected:** a small popup; destructive preprocessing; averaging conflicting breakline Z; silently excluding source data. The plan is better because the problem needs a canvas, source list, durable drafts, diagnostics, and recovery.  
**Tunable:** sampling defaults, preview thresholds, and crop interpolation tolerance.

#### GAP-D8 — Quantity report, solid, and difference raster are separate canonical products

**Decision:** Keep `mesh.volume.compute/save_report` unchanged; add Mesh-owned solids between two evaluable surfaces, a cloud mean-grid solid side, and strata-derived solids; add a Raster-owned signed height-difference Grid plus legend. All cite shared Mesh evaluators and Pointcloud sampling without taking their ownership.  
**Derivation:** S11; X1/X3/X7; MT-D8/MT-D20; Raster RA-D5/RA-D7; Pointcloud PC-D8/PC-D10.  
**Rejected:** claiming a numeric report is a solid; assigning all difference products to PC-D10; triangle fabrication for the cloud side when S11 explicitly requests a mean grid.  
**Tunable:** grid spacing, legend classes, and preview LOD—not sign, datum, valid footprint, or source revisions.

#### GAP-D9 — Plan combines a dedicated OS window with an infinite canvas

**Decision:** Preserve PE-D1's dedicated one-writer OS window, exact capture, persistence, and close lifecycle. Inside it, place finite sheets on an infinite canvas and replace fixed rails with tokenized floating/dockable top/left/right islands.  
**Derivation:** S6; B3; PE-D1/PE-D14/PE-D15/PE-D18; UI UIP-D8/UIP-D9; X5.  
**Rejected:** reverting Plan to the current main-window island; keeping the fixed three-column layout at `plan-editor.md:126–127`. The program's separate window is better than the statement's unspecified host because it isolates a large compositor and preserves native lifecycle.  
**Tunable:** default island positions and snap zones.

#### GAP-D10 — Civil receives its own milestone before BIM/Plan integration

**Decision:** Insert a Civil work package after Mesh/Measure substrate and before BIM/coded import; create a Civil milestone rather than hiding it inside M4 terrain. Plan and Agent remain late consumers.  
**Derivation:** Master Plan §2 dependency rules and §4 graph; D7; Civil CIV-D5/CIV-D14; X7.  
**Rejected:** leaving Civil outside the program; implementing it after Plan; folding it into Mesh and losing domain ownership.  
**Tunable:** queue label/order numbers, not dependency edges.

#### GAP-D11 — S2 becomes a shared semantic visual language

**Decision:** UI Platform defines selected/active, support, anchor, direction, and component-edge semantic tokens and shapes; owning entity adapters supply eligible subcomponents. Exact colors are fixed by an in-repo visual artifact and shared tokens, not third-party screenshots or one-off literals.  
**Derivation:** S2/G5; Design System shared-token and no-one-off-control rules; E1; X4/X7.  
**Rejected:** generic orange outlines for every entity; literal unverified Trimble color matching; letting BIM and Draw style selection independently.  
**Tunable:** token values after contrast and both-theme certification.

## 3. Resolved user-perspective workflows

These narratives state the target amendment, including close/cancel/failure/recovery and the one canonical command path. They do not duplicate Civil's already complete §2.1–§2.6 narratives; Civil remains the authority for alignment, vertical, bands, corridor, slope, pit, and profile detail.

### 3.1 Line and point construction

The user activates **Line**. The construction bar shows acquisition, first-point X/Y/Z, pending second-point X/Y/Z, horizontal distance, direction, ΔZ, and slope. The first LMB click captures a point through DR-D12 snap precedence. Moving the pointer shows one live rubber band and updates Cartesian and polar values without journaling. The user either clicks the second point, locks a direction/angle and types length, or types the endpoint. Where vertical meaning applies, a field selector exposes absolute Z, ΔZ from the captured first point, or slope; incompatible and zero-run combinations name the error and cannot commit. Typing focuses the relevant field without pointer motion. Tab/Shift+Tab traverse fields; Up/Down cycles the visible pick candidates. Enter commits the valid line once; Escape reverts field, then constraint, then armed tool; closing the function preserves no half-line. Ctrl+Z removes the one created entity.

For **Point**, click and typed-coordinate paths use the same bar. **3D target** displays a tokenized reticle whose origin and orientation can be moved/rotated with the shared gizmo or typed transforms. In sparse clouds it is an estimation aid: the proposed coordinate, acquisition source, residual/fit confidence, and “estimated” state are visible. The user confirms one ordinary `draw.point.create`; no cloud sample or inferred plane silently becomes authoritative. Cancel/close publishes nothing; transform previews never journal; automation submits the same reticle transform and final coordinate.

### 3.2 Global control strip, selection modes, and P9 tree

The always-visible bottom strip contains Support geometry, Whole/Segments selection, 3D/2.5D/2D, selectable-kind filter, Labels, and compact history controls. **Segments** changes only the view-local selection token: clicking a polyline returns parent entity ID, revision, and segment locator; the document is unchanged. A segment-aware command receives that locator and produces an ordinary journaled parent edit. A source revision invalidates or remaps the token explicitly—never to a different silent segment.

The left taxonomy switches among Layer, Object tree, Type, Cloud class, and Attached project without changing entity identity. Each node shows hidden/reference/editable/inert; parents propagate after a reviewed preview and display Mixed in grey. The detail explains every effective cause. Global Support/Labels/kind controls are overlays/defaults and do not overwrite entity choices. Ctrl+click toggles rows; Ctrl+A selects the focused visible/paged set with the scope stated. A failed bulk update applies none. Closing the popover leaves state; display history can undo it, while document Ctrl+Z cannot.

Selection appearance is supplied by entity adapters: lines show selected semantic color plus direction; points use a square; symbols emphasize the anchor; support geometry uses its support token; BIM exposes only stable eligible corners/edges at the active detail level. Hidden/inert entities are not candidates; reference entities remain selectable/snappable but commands explain why editing is unavailable. Heavy clouds remain entity/tree selected rather than point-clickable, preserving UIP-D15.

### 3.3 Rigid section creation

The user selects a Draw line and chooses **Create section**. The panel captures the line revision, shows a direction arrow, permits reversing it, and accepts depth by pick/constrained/typed input. The chosen arrow/line specification is visible on plan before commit. **Create** journals one canonical section definition and opens a new View surface whose local X follows the line, local Y is project up/elevation, and depth clips only when explicitly supplied. Because the transform is rigid, source edits update live under P10; an invalid/deleted source shows an unresolved section rather than an old view. Pan/zoom/camera history is View-local. Close hides the surface but retains the named section; Delete is the explicit document command. This function does not mutate or replace VD-D1 axis clip planes and does not own Civil profiles.

### 3.4 Surface creation additions

The user preselects points/clouds/curves/Civil manifests and opens **Create surface…**. MT-D1's dedicated window captures exact source revisions and P4 scope. In the source table the user sets Points, Breakline, Form line, Outer boundary, or Hole. Cloud sampling offers Spatial step, Existing point nearest cell mean Z, and Synthetic cell center at mean Z; the estimate and resulting count are shown before Run. All samplers create or reference immutable job products and leave the source cloud unchanged.

The draft can add versioned exclusions: **outside active outer boundary** and **within distance of selected breaklines**, with source set, distance, order, and excluded count visible. Individual exclusions and automated rules live only in the draft unless a separately confirmed source command is invoked. **Draw crop boundary** arms a 2D polyline inside the Mesh canvas using Draw input/focus rules; each vertex's Z is evaluated against the explicitly selected surface/cloud policy, and ambiguity/NoData blocks closure with a jump target. Civil corridor/pit accelerators populate the same source table and never bypass Check.

Check reports crossing Z conflicts, degeneracy, holes, and rule outcomes. Safe fixes are explicit; uncertain geometry never gets an averaged Z. Run checkpoints; closing the window leaves named drafts, Cancel stops within the bound, restart resumes verified phases, and source revision mismatch rejects late publication. Commit creates one ElevationSurface and one document undo entry.

### 3.5 Solids and difference raster

For **Solid between surfaces**, the user selects two evaluable surfaces, establishes top/bottom or cut/fill sign, optional exact boundary, and output specification. Preflight shows CRS, datum, valid-footprint intersection, holes/NoData, crossings, and expected cell/overlay work. Crossing surfaces partition into signed regions; the assistant either creates one classified solid with source-revision provenance or refuses non-manifold/ambiguous topology. The existing MT-D8 report remains a separate Compute/Save outcome and can be generated from the same capture.

For a cloud side, the user first chooses a cell size and creates an immutable cell-mean evaluator: XY at cell center and Z at mean, with count/variance/empty-cell provenance. Mesh uses the evaluator directly and does not triangulate that side merely to satisfy the solid. For boreholes, a BIM/Specifications-owned stratum set must provide ordered interfaces, identifiers, units, and missing/crossing diagnostics; Mesh does not invent layers between incomplete logs.

For **Height difference raster**, the user selects any supported surface/cloud evaluators, sign, grid origin/resolution, boundary, NoData policy, and legend. Raster produces a signed canonical Grid and linked legend definition; every cell records the evaluator/version policy. Preview may reduce resolution, but final values do not. Source changes mark the product stale under P10; Regenerate is explicit or automatic only within a recorded X6 budget. Cancel publishes nothing, restart resumes partitions, and export uses File's plan/execute path.

## 7. E1 failable in-repository criteria

These criteria are the amendment baseline. Implementing specs must commit their captures/fixtures in-repo; third-party screenshots are not visual truth.

1. **GAP-V1 — Line input:** first point, pending Cartesian/polar values, active vertical mode, constraint, acquisition source, and valid/invalid state remain visible at 100% and 150% scale. Fail if Tab moves a candidate or Up/Down moves field focus.
2. **GAP-V2 — Selection semantics:** selected directed line, point square, symbol anchor, support geometry, and eligible BIM edge are distinguishable without color alone in both themes. Fail on literal one-off colors or whole-symbol flood highlight.
3. **GAP-V3 — Global strip:** every S3 control fits or enters one explicit overflow at the minimum supported width; current mode/state/history domain is readable and keyboard accessible. Fail if global label/support toggles erase entity choice.
4. **GAP-V4 — P9 tree:** all four states, Mixed, inherited causes, focus, hover, and bulk preview remain legible for layer/type/cloud/project examples. Fail if reference can edit or inert can select/snap.
5. **GAP-V5 — 3D reticle:** origin, axes, rotation handles, typed transform, estimated state, source/residual, and final coordinate are visible against sparse/dense clouds. Fail if preview resembles a committed point.
6. **GAP-V6 — Rigid section:** plan line, arrow, depth, exact local axes, source revision, and live/unresolved state agree between plan and opened view. Fail if it is visually indistinguishable from an axis clip plane.
7. **GAP-V7 — Surface source table:** role, sampling statistic, estimated/output counts, exclusion rules, crop acquisition, errors, and source-local badge are simultaneously inspectable. Fail if Form line and Breakline are indistinguishable.
8. **GAP-V8 — Crop/error behavior:** each ambiguous or NoData crop vertex links bidirectionally between canvas and error list; no failed region looks complete; source geometry never changes without a separate confirmation.
9. **GAP-V9 — Solid:** top/bottom/sign, crossings, valid footprint, holes, source revisions, specification, stale state, and report-vs-solid distinction are visible. Fail if a negative region is silently swapped or report is labeled solid.
10. **GAP-V10 — Difference raster:** sign convention, units, zero, min/max, NoData, resolution, sources/revisions, legend classes, and stale state are visible in viewport and Properties. Fail if preview LOD is presented as final resolution.
11. **GAP-V11 — Plan canvas:** finite paper edges remain unmistakable on the infinite canvas; islands can float/dock/restore without obscuring native close or changing paper coordinates. Fail if pan changes sheet geometry or island state enters the document journal.
